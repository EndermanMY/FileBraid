# FileBraid 节点与端口命名标准

2026-11-17，Q68–Q72 已确认。本标准适用于新增节点和端口。当前端口对照见文末。

## 1. 现行约定

| 位置 | 规则 | 现有例子 |
| --- | --- | --- |
| 节点标题 | 表明操作、对象或提供的策略，沿用节点库中已经定稿的词。相同标题同时用于画布、节点库、右键添加和拖线菜单 | 复制、按扩展名筛选、源目录、目标目录树 |
| 文件端口 | 默认命名「文件」。筛选、合并、排除或目录分配后仍叫「文件」 | 「按扩展名筛选」左「文件」、右「文件」 |
| 同类型端口的角色 | 同一侧需要辨认用途时加角色词。左侧接收，右侧提供 | 「排除文件」左侧有「文件」「排除文件」，两者都是文件 |
| 主操作的现有例外 | 「复制」左「输入文件」，右「输出文件」 | 「目标目录」左侧端口仍叫「文件」 |
| 策略端口 | 标签表达提供哪种设置。同一类策略共用端口名称 | 「流复制策略」提供「复制策略」，「SHA-256 校验」提供「校验策略」 |
| 目录树逐项端口 | 直接显示文件或文件夹名称，悬浮说明选取范围、归入位置或相对路径处理 | 目录树的根端口放在对应目录区域。「来源目录树」的「文件」旁写「输出全部文件」，「目标目录树」的「文件」旁写「写入目标根目录」 |
| 保存与兼容 | 界面名称和工作流标识分开维护，文字改名沿用节点及端口标识 | 「合并文件」沿用节点标识 `merge`，普通文件输入沿用 `files` |

现版有两处需要在新增节点时明确区分：

1. 「复制」的「输出文件」目前用于将复制计划绑定到「目标目录」，下游还拿不到已写入的文件。画布保留专用连线，编辑阶段的名称不能用来推断转码何时可以读文件。
2. 「来源目录树」的「文件」输入当前只接「源目录」，使用它选定的目录展开树。扩展名筛选也输出「文件」，但不能凭同名接到这个入口。

## 2. 新增节点标题

| 节点职责 | 模式 | 示例 |
| --- | --- | --- |
| 独立执行操作 | 简短动词，必要时带对象 | 复制、移动、同步、转码 |
| 文件选择或整理 | 动作加对象，必要时点明条件 | 合并文件、排除文件、按扩展名筛选 |
| 来源、目标和浏览 | 对象名加必要的角色限定 | 源目录、目标目录、来源目录树 |
| 提供可复用的执行设置 | 方法名加策略，校验算法沿用「算法名称＋校验」 | 标准复制策略、流复制策略、SHA-256 校验 |

先用一句话说明用户为什么添加该节点，再据此定标题。需要搜索的旧名或英文名可以作为别名登记；画布显示一个正式名称。品牌和算法大小写沿用项目词表，例如 Sony、BLAKE3、xxHash3-64。新增节点优先进入已有分类，分类名称只有在出现区别明确的一组节点时才新增。

## 3. 新增端口

- 先写明端口实际提供给下游的内容和可用时机，再选显示名称。文件集合用「文件」，纯目录位置用「目录」，执行设置用对应的「策略」或「设置」。文件的来源、筛选状态、相对路径和数量写进说明。
- 普通端口以左右位置表示方向。复制、移动、转码等主操作，可用「输入文件」「输出文件」表达处理前后角色。新增主操作只有在能提供实际产出时，才使用「输出文件」。有多个同类型入口时用能辨认用途的名称，例如「文件」「排除文件」。
- 配置、计划和执行结果分别声明。报告用「报告」或更明确的名称，例如「同步报告」。如果能力只提供报告，就只声明报告端口。同步若要输出文件，需要先定义是目标现状、发生变更的文件，还是另一种范围。
- 同一真实类型使用一致的颜色和基础名称。兼容菜单和提示以实际连接规则为准；同一类型还可有来源限制、阶段限制和连接数量限制。颜色之外同时提供文字和悬浮说明。
- 每个端口的说明应覆盖接收或提供的对象、必接或可选、是否可多连，以及容易影响理解的规则。动态端口用文件／目录名作标签，并说明是否递归、落到哪里、改名或更换根目录后连线如何处理。根端口放在对应目录路径下方、逐项列表上方，保留其输入或输出方向。
- 只改显示名时沿用标识。若改动类型、端口作用或执行时机，先写出旧工作流如何载入、已有连线如何解释，再决定是否迁移。画布、拖线菜单和引擎校验应认可同一组合法连接。

## 4. 主操作的命名示例

| 节点 | 建议的输入表达 | 建议的输出表达 | 必须先定义的行为 |
| --- | --- | --- | --- |
| 复制 | 输入文件、复制策略、校验策略 | 现版「输出文件」用于绑定目标。支持串联后才可提供实际写入的文件 | 每步的落盘位置、写入完成条件、所选校验的通过条件 |
| 转码 | 输入文件、转码设置 | 输出文件 | 成品路径、可交给下游的时机、上游失败如何处理 |
| 移动 | 输入文件，目录位置由节点设置或独立端口提供 | 输出文件 | 成功移动的判定、已有目标冲突、跨设备时的完成顺序 |
| 同步 | 源目录、目标目录，方向和规则独立声明 | 同步报告。文件输出按具体范围另行定义 | 单向或双向、删除与冲突规则、输出集合的范围 |

例：若日后支持「复制 → 转码」，复制步骤应在文件已成功写入且通过已配置校验后交给转码。文件从哪里读取、逐文件还是按批次交付，需在实现转码串联时明确。

## 5. 新节点提交时的核对表

- [ ] 写出正式标题、所属分类和一句用途，确认节点库、画布、菜单和提示使用同一显示名。
- [ ] 每个端口写明显示名、方向、稳定标识、数据类型、可用时机、必接性、连接数量、兼容对象、悬浮说明。
- [ ] 动态端口说明行标签、路径规则和树项变更对连线的影响。
- [ ] 写出一条能连、至少一条不应连接的路径。涉及写入、删除、覆盖或多步骤的操作，同时说明预览内容、成功和失败时交给下游的东西。
- [ ] 验证旧工作流载入、当前工作流保存重开，核对画布和引擎对连接的判断。
