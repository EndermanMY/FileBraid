## 产品与边界

- 2026-11-16 测试交付采用 Windows x64 免安装压缩包，解压完整目录后运行 FileBraid.exe；正式安装程序留待后续发布验证。

- 产品是通用节点式文件归档与整理桌面软件；影视拷卡为首个重点模块。
- 2026-11-16 再次确认通用文件备份、复制与管理定位，节点化搭建可直观看懂的处理流程是产品特色。后续 Q54–Q57 已确认：首批服务经常整理、分发和备份大量文件的个人与小型团队；DIT 保留为专业官方工作流。核心标准为执行前看懂文件去向、执行过程可检查、执行结果可追溯。
- 2026-11-16 下一阶段顺序已确认：可靠复制归档发布验证 → 工作流重复执行 → 历史版本与还原。日常运行支持从保存的工作流检查来源与目标、查看本次文件变化、加入工作队列，无需重新编辑节点；画布保留为编辑中心。原因是优先保障真实文件任务可靠交付，再拓展备份能力。
- 2026-11-16 品牌最终确定为「织序 FileBraid」，替代本轮此前的中文待定及候选名称记录。中文表达通过编排使文件处理有序，英文保留文件与编织流程的含义。项目介绍采用新名称，程序、发布标识和启动入口的工程迁移尚未完成；名称注册可用性尚未核验。
- 首版通用动作是复制归档。移动、批量改名、删除、自动去重和媒体转换列入后续范围。
- 首批相机：Sony FX3、A7M4（α7 IV）、ZV-E1。未知结构退回完整目录复制；不能仅凭型号承诺所有录制模式适配。
- 影视来源卡只读：不写报告、不改名、不删除、不格式化。官方工作流独立保留每卡边界及必要相对结构。
- 机位由项目定义，软件可以建议，用户确认。拍摄日期由用户确认，禁止自动用文件修改时间替代。日期输入原使用任务参数栏，现由目录节点设置。
- 一卡多目标作为任务，卡间排队；目标默认并行，慢盘或失败盘不阻塞其他目标。允许有界缓冲及必要的源文件重读，不强求源卡只读一次。
- 首版支持 Windows 文件系统可访问的本地盘、移动盘与网络共享；云 API、SFTP、对象存储后续扩展。

## 官方工作流与自定义

- 官方工作流保持可重新使用，修改时另存为自定义工作流。
- 官方影视工作流默认完整双目标、SHA-256、保留卡边界、不接入文件内续传。
- 自定义工作流允许跨卡目录合并、类别分流以及显式拆分素材包；不强制所有用户沿用官方目录模板。
- 相机解析产生素材包，普通筛选不能悄悄拆散依赖。自定义工作流用显式“拆分素材包”节点取得文件级自由度，预览展示未包含的关联内容。
- 未经验证的相机关联文件默认保留；经过真实样卡验证后才开放对应的精细筛选规则。
- 早期设计采用独立参数页；已被「目录名称直接保存在工作流节点中」的决定替代。

## 交互与工作流

- React 节点画布表达来源、解析、筛选、目录映射、复制目标及策略。连线传递文件清单与素材信息；只在复制执行阶段写素材。
- 编辑不触发复制。执行前生成真实文件级计划，展示排除项、依赖、目标路径和冲突。
- 目录模板节点以树编辑目标层级，并由工作流保存。固定文本与变量组合是早期设计，变量已改为载入旧工作流时转换为具体名称。
- 不允许目标映射逃出目标根目录；非法名称、旧版缺失变量和路径冲突在执行前处理。
- 筛选同时支持规则选择与逐项选择。来源卡内容不因排除而被删除。
- 同一来源文件经多个分支到同一目标路径只复制一次，保留命中规则；到不同路径则分别复制。
- 不同来源文件到同一路径不得静默覆盖，未解决冲突阻止执行。首版无批量改名动作，不自动把重命名策略算作已交付能力。
- 首版内置节点，支持分支，不支持循环、任意脚本、第三方代码插件。工作流可导入导出，保存节点与工作流版本。
- 排队任务保存当前工作流快照，后续编辑不修改已有任务。

## 复制、恢复与结果

- 已有同名目标先校验，一致则复用；不一致暂停冲突项，由用户决定另存或明确替换。
- 明确替换时先复制到临时位置并校验，再提交替换；此前保留旧文件。
- 可取消单个目标或整个任务；保留已通过校验的文件，未完成内容使用明确的临时文件形式。
- 基础文件级恢复与可选文件内续传不同。恢复时检查来源匹配，不能把同路径直接等同于同来源。
- 文件内续传作为传输策略节点连接复制目标，可一对多。未连接则未完成文件重拷；连接后检查来源变化并校验完整最终文件。
- 某个目标失败时其他目标继续；失败目标可独立重试。
- 每个文件只对工作流指定的目标负责，不要求所有目标获得同一内容。预览显示只有一份输出的素材。
- 选择了校验的输出必须全部通过才可宣称全部校验通过。自定义无校验任务仅显示“复制完成，未校验”；所有复制成功但仅部分目标校验时显示“复制完成，部分未校验”。
- 无算法节点时，已有文件复用判断和明确替换前的保护性验证仍使用 SHA-256；预览与报告说明这些额外检查，不据此宣称其余文件均已校验。
- 执行开始复核来源清单，发现新增、缺失或可检测变化时暂停该任务并要求重新预览，不静默改变范围；其他独立任务不受影响。检测机制待工程验证，元数据相同不等于内容一定未变。
- 复制中检测到来源文件变化时暂停受影响任务，该文件在所有目标上的结果需要重新处理，不标为通过；保留其他已验证结果，重新预览后再处理。
- 来源确认未变但目标校验不匹配时，默认完整重拷该文件一次并重验；再次失败则等待用户处理。保留失败与重试历史，其他目标继续；来源变化不适用自动重拷规则。
- 恢复时核对目标卷身份、路径和任务记录，不能只凭盘符、卷名或挂载路径确认目标。无法可靠确认时由用户重新选择；换盘重新检查内容，不继承旧盘完成状态。

## 六种校验模块

- CRC32、BLAKE3、MD5、SHA-1、SHA-256、xxHash3-64 各自独立为策略节点。
- 策略连接复制目标，一节点可服务多个目标；单目标可以组合多算法，所有选定算法必须匹配。
- 引擎负责源数据摘要计算、目标重新读取及比较，不要求用户拼接两侧哈希和比较步骤。
- 尽量一次读取计算多个算法。算法变体、字节序、输出格式与库待核验，不把名称相同当作必然互操作。
- 允许自定义工作流不连接算法，但不能显示校验通过。
- 支持独立复验：源目标按相对路径比较，或根据本软件清单复验；第三方格式后续适配。

## 记录与报告

- 本地任务记录负责恢复；HTML 供阅读交接，JSON 保存可机器处理的清单。
- 记录工作流快照、源目标路径、大小、摘要、排除原因与逐文件逐目标状态。
- 目标保存相关报告，电脑本地保留完整记录。报告区分复制、复用、排除、失败、未完成及未校验。
- 筛选后的任务描述为“所选素材”，不能误称完整整卡备份。
- ASC MHL 兼容为后续独立里程碑。
- 数据校验成功而报告写入失败时，分别呈现数据成功与报告失败，不宣称完整交付结束；允许单独重试报告，不重复复制已验证内容。

## 技术与发布

- React + TypeScript 界面，Electron 窗口/托盘/系统交互，Rust 独立执行进程；旧 C# 实现作为参考，不保留双执行引擎。
- 文件数据不穿过 UI 通信层。Rust 再检查工作流，管理任务、复制、算法、恢复及报告。
- 自有版本化工作流模型独立于节点 UI 库。节点库、进程协议、任务存储组件尚未定型。
- 首版本机进程通信，不开放 Web 服务；通过可替换接口为未来 Web 入口留空间。
- 关闭窗口继续托盘执行；明确退出时选择取消退出或返回继续。
- Electron 宿主异常退出时，Rust 引擎停止安排新文件，安全中止当前写入并保存恢复状态；重启后由用户恢复，保留已完成且验证的文件。这不同于主动关闭窗口后的托盘运行。
- 先验证可独立启动的 Windows Demo，再加入 Apple Silicon Mac 构建、权限与设备测试；Intel Mac 后续考虑。
- Demo 阶段隔离平台接口，但不宣称 Mac 已兼容。没有真实平台与设备测试就不能视为通过。

## Windows Demo 开发阶段补记（2026-11-16）

### 画布和端点

- 参考 Unreal Engine 和 ComfyUI。左侧节点库支持分类和搜索；画布右键菜单按分类展开添加节点；选中节点或连线后可用右键或 Delete 删除。默认左键拖动空白处平移，Ctrl 加左键拖动框选。右上只放「加入队列」，工作流操作放在左上。
- Windows 使用内嵌标题栏，去掉独立系统菜单行。第一行显示应用名称和原生窗口控件，空白处可拖动窗口；原先同行的工作区切换、恢复任务和加入队列移到第二行。[Electron 自定义标题栏](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar)
- 画布接收键盘操作时去掉外围焦点框。节点、连线和按钮保留各自的选中或焦点提示。
- 左侧以「节点库 / 工作流库」切换。「工作流库」包含「官方工作流」和「我的工作流」，以及打开和保存 JSON 文件的入口。「预设」与「工作流」原指同一份可复用规则，统一使用「工作流」。缩小窗口时画布随窗口收缩，侧栏内容独立滚动。
- 取消任务参数栏。工作流 v3 将目录名称直接存入节点，保存工作流即可复用。载入旧版时把已填写的变量展开成名称，缺失的值在对应目录节点中补齐。详见 [ADR 0006](adr/0006-directory-names-in-workflows.md)。
- 节点左进右出，控件直接呈现在各节点内。拖动连接点到空白处时，显示兼容节点，选择后自动连线。重接已有连线时拖到空白处可断开，端口也支持通过右键或 Alt 加单击断开。
- 「文件输入」「目录树输入」「目录树输出」「文件输出」归入「输入与输出」。「目录树输入」是原「目录树分流」的统一名称，旧工作流使用同一节点标识。「文件输入」和「文件输出」分别指定来源根目录与复制目标。

### 文件选择和路由

- 选择来源根目录后逐层展开。文件和文件夹所在行直接显示输出连接点，从行上拖线即可分流到不同目标。此前的「+」创建端口方案已被替代。整个根目录仍可从「全部文件输出」输出。
- 文件端口选取一项，文件夹端口选取其后代文件，按来源根目录保留相对路径。目录模板可在后续更改落盘路径。收起分支或滚出目录树时，已连接项目仍可通过按路径标记的端口操作；切换来源根目录后逐项连线需要重连。
- 「目录树输入」左侧可接入一个「文件输入」，连接后使用该节点的来源目录。右侧保持整棵树与逐项两个输出方式。未连接时，旧工作流及新节点仍可在节点内选目录。
- 「目录树输出」与「目录树输入」镜像交互：右侧直接连接一个已选目录的「文件输出」后，展开实际目标目录树，每个现有文件夹左侧都有接收端口。文件供查看，目录供连接。多个来源可接到同一目标文件夹，同一来源也可接到多个文件夹。直接逐项连接时，单文件直接放进目标目录，文件夹连同自身名称和内部结构放进去。
- 实际文件夹连线随目标根目录变化而断开。入队及执行前检查所选文件夹是否仍存在。规划目录可编辑名称与层级，改名保留其连线，删除分支时断开所属连线。单一路径前缀仍可用「目录模板」。
- 两个目录树节点的主端口按对角线镜像排列。「目录树输入」左上为「来源根目录输入」，右下为「全部文件输出」。「目录树输出」左下为「全部文件输入」（原「目标根目录输入」），右上为「汇总文件输出」。左下端口接收直接落到目标根目录的清单。
- 「清单合并」多线输入，以来源文件与落盘相对路径的组合去重；同一来源映射到两个不同位置时保留两份计划。同一路径收到不同源文件时，入队时报冲突。
- 「清单相减」接收主清单与排除清单，以完整来源路径匹配。同名但位于不同目录的文件独立处理。它只改变计划中的选择。
- 「扩展名筛选」在一条清单上按统一规则保留或排除扩展名，空规则保留全部。拆分影视素材包仍遵照官方工作流与自定义边界。

### 复制、队列与校验

- 工作流 v2 要求每个「文件输出」明确连接一项复制策略。缺少策略时不能入队，同一目标只接受「标准复制」或「快速流复制」之一；策略可以复用于多个目标。「标准复制」将旧版的隐式通用文件流变为独立节点，也是官方双目标工作流的策略。打开 v1 工作流时只为缺少策略的目标补接「标准复制」，已有快速流配置照常使用。详见 [ADR 0005](adr/0005-explicit-copy-strategy.md)。
- 「快速流复制」为文件输出提供独立复制策略。参考 FastCopy 区分同机械盘分批读写与不同设备并行读写。节点可设置主缓冲区、单次 I/O 大小、在途缓冲块数、小文件阈值、限速和 Windows 低 I/O 优先级。主缓冲区无产品侧固定上限，至少容纳一个 I/O 块；实际分配随文件与模式变化。
- 快速复制的当前实现使用应用层缓冲和系统缓存。FastCopy 的无缓存 Direct I/O、按文件系统设置小文件写缓存阈值、目录批读等作为后续可验证的优化方向。
- 文件级落盘预览在「工作队列」展示。「加入队列」生成计划并固定工作流快照，开始执行另行触发。任务显示所使用的库内工作流名称，无名称时使用任务编号。队列集中展示逐目标进度、速率曲线、结果和报告导出。横轴显示任务经过时间的可见窗口，纵轴显示实际复制吞吐量。
- 各校验策略可选「边复制边校验」或「复制完再校验」。前者是每个文件写完后读取目标进行校验，后者先完成该目标的写入再逐个读取校验。同一目标上的多个算法共用校验时机。仅复验是对既有输出做只读检查。
