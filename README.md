# 织序 FileBraid

织序FileBraid是节点式文件复制、备份与整理桌面应用。通过节点搭建、预览和执行文件处理工作流，影视拷卡是其中的专业场景。产品设计和验收范围见 [设计文档](docs/README.md)。

项目名称统一为织序 FileBraid；旧版工作流和任务记录继续使用原数据目录。

本仓库目前尚未选择开源许可证；第三方依赖各自的许可证仍然适用。

项目包含 Electron 桌面界面、React Flow 工作流画布和 Rust 复制引擎。当前处于 Windows Demo 阶段，macOS 构建和真实设备故障场景仍需验证。历史 WPF 源码保存在原项目仓库。

## 画布操作

- 选中路径节点后，拖动右下角控制点调整宽度和高度。路径可以换行，目录树加高后能一次显示更多行。
- Ctrl 加左键拖动可以框选。在画布或节点上右键打开「整理」侧边子菜单，可对齐所选节点。没有选中节点时，整理作用于整个画布。整理只沿选定方向收紧间距，保持另一轴的位置，并为相邻节点留出间距。多选后可建组或移出组，拖动整条组标题栏可移动成员，组内空白仍用于画布操作。右键组标题栏可重命名。组和节点尺寸随工作流保存。
- 选中的节点显示在未选中节点上方，最近点击或拖动的选中节点优先。缩放低于 35% 时画布隐藏节点文字，右下角工具条可切换选择（V）和拖拽（H）、适配视图、缩放以及显示连线。小地图（Alt+M）悬浮在画布右下角，支持平移、缩放和切换节点颜色、曲线连线、分组图层。
- 拖动端口圆点可新建连线。拖动端口旁的线尾可重接，松在画布空白处可断开，松在不兼容的端口会保留原连接。多条线共用一个端口时，先单击线身或在端口右键菜单中选中一条，再拖动共用端的线尾。

## 运行测试

```powershell
npm test
cargo test --locked --manifest-path engine/Cargo.toml
npm run build:engine
npm run build
npm run test:desktop
```

桌面测试会以独立配置打开 Electron，使用临时文件夹走真实的入队、复制、校验与取消流程。运行前需已安装项目依赖。

## 在 Windows 上启动

Windows x64 测试包解压后，双击目录内的 `FileBraid.exe`。整个目录需要保持完整；这是早期测试版，建议使用测试数据体验。

在文件资源管理器中双击 [Start-FileBraid.cmd](Start-FileBraid.cmd)，即可打开工作区里已构建的版本。首次构建或更新源码后，请按以下步骤构建。

Windows 标题栏右侧可最小化、最大化／还原或关闭窗口。拖动标题栏空白处可移动窗口，工作区切换和任务操作位于下一行。

准备 Node.js 24（含 npm）和可构建 Windows 原生程序的 Rust 工具链。在工作区根目录执行：

```powershell
npm install
npm start
```

打开左侧「工作流库」即可载入「官方工作流」中的「双目标工作流」。画布中的「文件操作」分类提供「复制」节点，通过「输入文件」接收要复制的文件，再将「输出文件」接到对应「目标目录」的「文件」端口。复制策略必接，校验策略可选。双目标使用两个复制节点，可以共用文件清单或策略。打开旧工作流时会为每个原「文件输出」插入复制节点。编辑完成后输入名称，点击「存到工作流库」，即可在「我的工作流」中再次载入。用同一侧栏内的「打开工作流文件」和「保存工作流文件」可导入或导出 JSON 文件。

在节点内分别选择来源和两个目标目录，再点击「加入队列」。工作队列保存当前工作流的快照并显示落盘清单。可以单独开始复制或复验，也可以按入队顺序运行当前待办任务。点击开始后直接执行，以当前预览为准检查来源和目标身份。任务运行时可在详情中暂停、继续或取消当前任务。任务结束后，可用「重置任务」重新预览并回到待执行，已写入文件会保留。已完成项按成功文件计数，取消和失败另计。目标总进度按实际写入与校验字节累计。选择「复制完再校验」时，全部写入后总进度到 50%。文件列表用图标显示状态，进行中的圆环按当前文件阶段的字节进度填充。蓝色弯箭头表示「已跳过」，可展开「状态说明」查看原因。来源和目标哈希分别显示首尾四位，悬浮可看完整摘要。工作队列固定在窗口内。文件列表独立滚动，可查看全部输出并拖动表头分隔线调整列宽。「自动滚动到当前文件」开启时跟随正在处理的文件，并行任务优先跟随首个正在处理的目标。「停止队列」会取消当前任务并保留其余待执行项。传输图分别显示复制写入和校验读取的实时合计，各目标显示当前阶段的速度。图表采用固定的 60 秒时间窗口，写入与校验读取在同一张图中显示，可点击图例分别隐藏或显示。任务运行时纵轴跟随最近速率，超出刻度的历史峰值另行标注。任务预览按目标列出需要新写入的文件数和已有文件数。每项任务可分别导出 HTML 或 JSON。待执行队列保存在当前程序会话，已开始的复制任务继续写入本地恢复记录。

官方双目标工作流使用 SHA-256。可将「CRC32 校验」「BLAKE3 校验」「MD5 校验」「SHA-1 校验」「SHA-256 校验」和「xxHash3-64 校验」组合连接到同一个「复制」节点，所有已选算法均匹配才通过。报告列出各算法结果。仅复验默认在未配置算法时使用 SHA-256。

「输入与输出」分类包含「源目录」「来源目录树」「目标目录树」「目标目录」。「来源目录树」左侧的「文件」可接「源目录」，也可在节点内直接选择来源目录。来源目录路径下方的右侧「文件」端口输出整棵树，文件和文件夹行上的连接点沿节点右边缘排列，可以单独拖线。目录列表的滚动条在左侧。文件夹端口包含后代文件，各项保留相对来源根目录的路径。

把「目标目录树」右侧的「文件」接到「复制」的「输入文件」，再将「输出文件」接到已选定的「目标目录」，即可在「目标目录树」展开实际目标目录。将来源文件的右侧连接点拖到目标文件夹的左侧连接点，即可把文件放进该文件夹。同一文件可连到多个文件夹，一个文件夹也可接收多条线。已有文件显示在树中供查看。输出目录区域带「写入目标根目录」说明的「文件」端口接收直接归入目标根目录的文件。

「Sony 素材分类」左侧接文件，右侧可选「全部文件」「照片文件」「视频文件」「代理文件」「卡管理文件」「LUT 文件」「其他文件」。视频输出会带上能按名称配对的片段 XML 和缩略图。分类输出可接到「目标目录树」的不同文件夹，也可各接一个「复制」节点。分流保留来源相对路径，未送往任何目标的文件可在入队预览中查看。整卡归档请连接「全部文件」。上游选定介质或目录后，节点会显示 Sony 目录识别状态。入队时还会检查 Sony 拍摄目录与卡标记，或验证与片段匹配的 Sony XML。通用文件可直接走「双目标工作流」。

「拍摄介质」在 Windows 上自动刷新已挂载的拍摄设备。插入后在节点中选择设备，再将右侧「文件」接到「来源目录树」「Sony 素材分类」或「复制」。入队及开始执行时会检查所选设备身份。HTML 和 JSON 报告记录介质类型、系统可读取的介质型号和序列号，并单列系统设备字段；USB 读卡器只暴露桥接信息时，卡本身的字段保持未读取，节点会单列 Windows 设备序列号。

在「目标目录树」的「规划目录」中，可添加顶层文件夹，也可用每行的「＋同级」「＋子级」扩展结构。用「↑」「↓」调整同级文件夹的顺序。子文件夹前的连线标示所属层级，排序会随工作流保存。把文件连到相应的文件夹端口即可指定去向。改名会保留连线，移除文件夹会断开该目录及下级连线。规划的文件夹会在有文件写入时创建。

「合并文件」接收多路文件，相同源路径和输出路径只保留一次。「排除文件」按完整来源路径排除匹配项。「按扩展名筛选」可保留或排除匹配项，留空保留全部。路径冲突在加入队列时报错。

每个校验节点可选择「边复制边校验」或「复制完再校验」。前者每个文件完成写入后立即重读校验，再处理该目标的下一个文件。后者先为该目标写完临时文件，再统一重读校验，每个文件通过后提交到正式路径。各目标独立推进，同一目标上的算法使用同一个时机。旧工作流默认逐文件校验。

每个「复制」的「复制策略」端口必须连接一个节点，才可加入队列。可以选择「标准复制策略」或「流复制策略」，同一策略节点可连到多个复制节点。「标准复制策略」使用通用文件流，也是官方双目标工作流的默认策略。打开第 1 版工作流时，会为原先没有策略的目标补上「标准复制策略」。

「流复制策略」默认主缓冲区 32 MiB、I/O 单位 2 MiB、在途缓冲块 8 个、小文件阈值 128 KiB。限速 0 表示全速。已保存的显式参数和旧版数字块大小仍可使用。主缓冲区须容纳一个 I/O 块，软件无固定单目标或任务总量上限，执行时按文件和传输模式申请内存。

并行模式同时读写，实际在途块数取配置块数和缓冲区可容纳块数中的较小值。有效块数为 1 时同步读写。分批模式先读满缓冲区或读到文件末尾，再按块写出，队列深度不参与调度。自动模式查询 Windows 盘符对应卷的磁盘区段和寻道信息，能确认共享机械设备时选择分批。无法查询的同盘符使用分批，其他未知情况使用并行。旧读卡器可以手动选择并行模式并把在途数设为 1，使复制改用单块同步读写。低 I/O 优先级使用 Windows 线程后台模式。

小文件或仅需单个 I/O 块的输出走轻量流，复用每个目标的缓冲区。快流当前使用系统缓存与普通文件句柄，队列深度表示应用层缓冲块数。限速适用于复制写入，不限制校验读回。缓存刷新、目标重读校验和同名文件保护均适用。进度区按目标显示文件数、字节数、当前阶段和该阶段速率。

```powershell

```

## 开发状态

Windows 工作区已通过前端构建、13 项 Node 测试、4 项 Rust 集成测试和 Electron 桌面回归。已验证双物理盘复制、已有文件复用、冲突保护、队列控制和 HTML／JSON 导出。Sony FX3 样卡与 USB 直连介质经过只读预览。Windows x64 免安装测试包为 `FileBraid-v0.1.2-Windows-x64-test.zip`。完整解压后双击 `FileBraid.exe`。发布验证见[路线图](docs/ROADMAP.md#2026-11-18-v012-windows-测试包)。

任务会在本机应用数据目录保存工作流和逐文件结果。重新打开后可点击「载入上次任务」，重新加入队列生成预览，再按当前来源校验已有目标文件。执行时核对当前预览的目录身份与来源清单，旧结果仅供查看。已用 Windows 本地目录验证截断记录、复用和目标目录替换。实际拔盘、SMB 共享和新版桌面恢复交互尚待测试。

规划目录的名称、层级和连线随工作流保存，可存入工作流库，也可保存为工作流 JSON 文件。旧版「目录模板」打开时会转换成「目标目录树」，原输入接到最深层的文件夹，保留原落盘路径。已填写的旧变量会展开为目录名称，缺失的变量需要补上实际名称。已有文件冲突时可调整目标路径继续。显式替换、文件内续传、清单复验、报告自动保存、托盘和独立打包仍在后续工作中。

### 节点端口

普通文件端口显示「文件」，左右位置表示输入与输出。同一节点有多个文件端口时，使用「输入文件」「输出文件」或「视频文件」等标签区分用途。相减节点的「排除文件」用于指定需要排除的来源文件，不会删除原文件。目录树逐行连接点保留文件或文件夹名称；悬停可查看选取范围、目标位置及连接要求。

「复制」的「输出文件」表示计划写入的文件。连接「目标目录」并启动队列任务后，才会实际写入。
