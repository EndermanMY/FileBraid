# 织序 FileBraid

织序 FileBraid（原名 CardHelper）是节点式文件复制、备份与整理桌面应用。通过节点搭建、预览和执行文件处理工作流，影视拷卡是其中的专业场景。产品设计和验收范围见 [设计文档](docs/README.md)。

品牌名称已确定；当前程序、启动入口和内部工程标识仍使用 CardHelper，工程更名尚未完成。

本仓库目前尚未选择开源许可证；第三方依赖各自的许可证仍然适用。

项目包含 Electron 桌面界面、React Flow 工作流画布和 Rust 复制引擎。当前处于 Windows Demo 阶段，macOS 构建和真实设备故障场景仍需验证。历史 WPF 源码保存在原 CardHelper 仓库。

## 在 Windows 上启动

在文件资源管理器中双击 [Start-CardHelper.cmd](Start-CardHelper.cmd)，即可打开工作区里已构建的版本。首次构建或更新源码后，请按以下步骤构建。

Windows 标题栏右侧可最小化、最大化／还原或关闭窗口。拖动标题栏空白处可移动窗口，工作区切换和任务操作位于下一行。

准备 Node.js 24（含 npm）和可构建 Windows 原生程序的 Rust 工具链。在工作区根目录执行：

```powershell
npm install
npm start
```

打开左侧「工作流库」即可载入「官方工作流」中的「双目标工作流」。编辑完成后输入名称，点击「存到工作流库」，即可在「我的工作流」中再次载入。用同一侧栏内的「打开工作流文件」和「保存工作流文件」可导入或导出 JSON 文件。

在节点内分别选择来源和两个目标目录，再点击「加入队列」。工作队列保存当前工作流的快照并显示落盘清单。可以单独开始复制或复验，也可以按入队顺序运行当前待办任务，每项任务执行前都须确认。「停止队列」会取消当前任务并保留其余待执行项。进度与最近一分钟的实际复制速率按目标显示，每项任务分别导出 HTML 或 JSON。待执行队列保存在当前程序会话，已开始的复制任务继续写入本地恢复记录。

官方双目标工作流使用 SHA-256。可将 CRC32、BLAKE3、MD5、SHA-1、SHA-256 和 xxHash3-64 节点组合连接到一个目标，所有已选算法均匹配才通过。报告列出各算法结果。仅复验默认在未配置算法时使用 SHA-256。

「输入与输出」分类包含「文件输入」「目录树输入」「目录树输出」「文件输出」。「目录树输入」左侧的「来源根目录输入」可接「文件输入」，也可在节点内直接选择来源目录。右侧「全部文件输出」输出整棵树，文件和文件夹行上的连接点可以单独拖线。文件夹端口包含后代文件，各项保留相对来源根目录的路径。

把「目录树输出」右上方的「汇总文件输出」接到一个已选择落盘根目录的「文件输出」，再点击「展开输出目录树」。将来源文件的右侧连接点拖到目标文件夹的左侧连接点，即可把文件放进该文件夹。同一文件可连到多个文件夹，一个文件夹也可接收多条线。已有文件显示在树中供查看。左下方的「全部文件输入」接收直接落到目标根目录的清单。

「添加规划文件夹」可定义尚未创建的目录。对规划目录改名会保留连线，删除目录会断开该目录及下级连线。规划目录仅在有文件要写入时创建。

清单合并接收多条路线，相同源路径和输出路径只保留一次。清单相减按完整来源路径从主清单去掉排除清单中的文件。扩展名筛选可保留或排除匹配项，留空保留全部。路径冲突在加入队列时报错。

每个校验节点可选择「边复制边校验」或「复制完再校验」。前者每个文件完成写入后立即重读校验，再处理该目标的下一个文件。后者先为该目标写完临时文件，再统一重读校验，每个文件通过后提交到正式路径。各目标独立推进，同一目标上的算法使用同一个时机。旧工作流默认逐文件校验。

每个「文件输出」的「复制策略」端口必须连接一个节点，才可加入队列。可以选择「标准复制」或「快速流复制」，同一策略节点可连到多个目标。「标准复制」使用通用文件流，也是官方双目标工作流的默认策略。打开旧工作流时，原先没有策略的目标会自动接上「标准复制」。

「快速流复制」默认主缓冲区 32 MiB、I/O 单位 2 MiB、在途缓冲块 8 个、小文件阈值 128 KiB。限速 0 表示全速。已保存的显式参数和旧版数字块大小仍可使用。主缓冲区须容纳一个 I/O 块，软件无固定单目标或任务总量上限，执行时按文件和传输模式申请内存。

并行模式同时读写，实际在途块数取配置块数和缓冲区可容纳块数中的较小值。有效块数为 1 时同步读写。分批模式先读满缓冲区或读到文件末尾，再按块写出，队列深度不参与调度。自动模式查询 Windows 盘符对应卷的磁盘区段和寻道信息，能确认共享机械设备时选择分批。无法查询的同盘符使用分批，其他未知情况使用并行。旧读卡器可以手动选择并行模式并把在途数设为 1，使复制改用单块同步读写。低 I/O 优先级使用 Windows 线程后台模式。

小文件或仅需单个 I/O 块的输出走轻量流，复用每个目标的缓冲区。快流当前使用系统缓存与普通文件句柄，队列深度表示应用层缓冲块数。限速适用于复制写入，不限制校验读回。缓存刷新、目标重读校验和同名文件保护均适用。进度区按目标显示文件数、字节数、当前阶段和该阶段速率。

不安装应用依赖也可以验证 Node 进程桥接：

```powershell
node --test desktop/preview.test.cjs
```

## 开发状态

Windows 已通过 Rust 编译、TypeScript 检查和前端构建。上一版通过桌面界面验证模拟 Sony 卡的双目标预览。本次通过 Node 进程桥与 Rust 引擎验证真实复制、已知 SHA-256 摘要、冲突隔离、内容复用、过期预览拒绝及取消。新版桌面复制与导出交互仍待联调。

任务会在本机应用数据目录保存工作流和逐文件结果。重新打开后可点击「载入上次任务」，重新预览并确认，再按当前来源校验已有目标文件。恢复时会比较目录身份和来源清单，旧结果仅供查看。已用 Windows 本地目录验证截断记录、复用和目标目录替换。实际拔盘、SMB 共享和新版桌面恢复交互尚待测试。

目录名称直接在「目录模板」或「目录树输出」里编辑，随工作流保存。载入旧工作流时，已经填写的变量值会转换为具体目录名称。缺失的变量需要在对应目录节点里补上实际名称。已有文件冲突时可调整目标路径继续。显式替换、文件内续传、清单复验、报告自动保存、托盘和独立打包仍在后续工作中。
